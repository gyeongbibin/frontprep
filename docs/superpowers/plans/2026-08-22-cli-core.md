# CLI Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the typed, tested Frontprep CLI runtime that detects supported projects, aggregates module intents, applies changes transactionally, verifies results, and exposes `frontprep init` and `frontprep check`.

**Architecture:** A Commander entry point delegates to command orchestrators with injected services. Modules return declarative intents; the core validates and aggregates them into an immutable plan, applies the plan through a rollback-capable transaction, and records deterministic state in `.frontprep.json`. Feature modules are injected through a registry, allowing this branch to test the complete core with fake modules without implementing feature policy.

**Tech Stack:** Node.js 22.22.1+, TypeScript 5.9, pnpm 10, Commander 14, Ajv 8, jsonc-parser 3, semver 7, yaml 2, picocolors 1, tsup 8, Vitest 4, ESLint 9.39, Prettier 3.

**Spec:** `docs/superpowers/specs/2026-08-22-frontprep-v1-design.md` and `docs/modules/cli-core.md`

## Global Constraints

- Package name is `@mingyeongbin/frontprep`; executable name is `frontprep`.
- Initial version is `0.1.0-beta.0`.
- Runtime engine is Node.js `>=22.22.1`; supported consumers use Next.js 16, TypeScript 5, and pnpm 10.
- The CLI is ESM and `dist/cli.js` retains `#!/usr/bin/env node`.
- Modules never write files or execute commands directly.
- Consumer JavaScript and TypeScript configuration is inspected as text and never imported.
- Paths are root-relative POSIX paths; absolute paths, parent traversal, NUL bytes, and symlink escapes are rejected.
- Child processes use argument arrays with `shell: false`.
- Generated text uses UTF-8, LF, and deterministic ordering.
- A first `init` requires clean Git state; an immediate rerun permits only canonical manifest-recorded changes.
- `.frontprep.json` is written only after successful module and project verification.
