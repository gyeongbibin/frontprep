> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the deterministic GitHub Actions and production-build module, then activate all five Frontprep v1 modules in the public CLI.

**Architecture:** A declarative `SetupModule` emits two script intents and one managed workflow intent. Existing core planning, ownership, verification, transaction, and rollback mechanisms apply those intents. The registry exports the fixed five-module production set, while an exact-Node acceptance test drives the built public CLI through a real Next.js production check.

**Tech Stack:** TypeScript 5.9, Node.js 22.22.1, pnpm 10.22, Vitest 4, YAML 2, Next.js 16, GitHub Actions

```ts
const MODULE_ID = 'ci' as const
const WORKFLOW_PATH = '.github/workflows/ci.yml'
const SCRIPTS = Object.freeze([
  ['frontprep:build', 'next build', 'owned'],
  ['frontprep:check', 'pnpm run frontprep:build', 'append-once'],
] as const satisfies readonly (readonly [string, string, ScriptPolicy])[])

function createIntents(): readonly ChangeIntent[] {
  return Object.freeze([
    ...SCRIPTS.map(([name, command, policy]) =>
      scriptIntent(
        MODULE_ID,
        name,
        command,
        policy,
        name === 'frontprep:build'
          ? 'CI provides the deterministic production build.'
          : 'CI adds the production build to the full check.',
      ),
    ),
    managedFileIntent(
      MODULE_ID,
      WORKFLOW_PATH,
      CI_WORKFLOW,
      0o644,
      'CI owns the GitHub Actions workflow.',
    ),
  ])
}
```

Use the exact `CI_WORKFLOW` bytes in `docs/modules/ci.md`. Escape the GitHub expression as `\${{ ... }}` inside the TypeScript template literal.

- [x] **Step 6: Implement analysis and verification**

Add a safe snapshot helper and canonical ownership rules:

```ts
async function workflowConflict(
  context: ProjectContext,
): Promise<VerificationIssue | null> {
  const snapshot = await safeSnapshot(new FileSystem(context.root))
  if (snapshot?.exists === false) return null
  if (
    snapshot !== null &&
    snapshot.bytes?.equals(Buffer.from(CI_WORKFLOW)) &&
    snapshot.mode === 0o644
  ) {
    return null
  }
  const recorded = context.manifest?.files[WORKFLOW_PATH]
  if (
    snapshot !== null &&
    recorded?.ownership === 'managed' &&
    recorded.hash === snapshot.hash
  ) {
    return null
  }
  return {
    message: `GitHub Actions workflow conflicts at ${WORKFLOW_PATH}.`,
    path: WORKFLOW_PATH,
  }
}
```

`analyze` throws `ConflictError` for that issue. `verify` does not accept the manifest exception: require exact workflow bytes and mode, exact `frontprep:build`, and a three-stage `frontprep:check` whose split-on-literal-`&&`, trimmed stages equal:

```ts
;[
  'pnpm run frontprep:quality',
  'pnpm run frontprep:test',
  'pnpm run frontprep:build',
]
```

Return frozen, path-sorted issues and `valid: issues.length === 0`.
